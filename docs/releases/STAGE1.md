## 建议展示顺序

### 第一部分：问题与最终答案

打开首页，说明研究的问题是“真实后训练更新是否转化为外部程序能力”，不是只展示 loss 曲线。直接展示完整五模型表格，说明两个种子的主对照方向不一致，不能只挑 seed44。

### 第二部分：现场复算

```bash
python scripts/stage1_release.py demo
python scripts/stage1_release.py verify
```

解释输出来自公开的逐题统计，不是假装实时跑7B。需要展示统计时，再执行 `verify --bootstrap`，把任务级重采样与候选级独立性区别讲清楚。

### 第三部分：工程难点与纠错

在总报告中展示三个具体问题：格式/粗执行奖励饱和导致零更新；宿主时限造成相同代码反馈漂移；参考解资源不足导致原评测停止。说明如何保存失败证据、明确修订协议并统一比较，而不是删除报错日志。

### 第四部分：可信度与限制

打开 manifest 展示模型和产物哈希。拥有 Tang 的私有产物时，运行只读 audit；没有时如实限定为公开复算。说明48任务/32步/两个种子的研究范围、同基准数据限制和后验案例选择。

## 已知限制与维护状态

本版本暂停新增训练。原始程序、隐藏测试、权重、镜像及完整离线环境没有随源码交付；部分历史训练入口依赖 Tang 主机名与固定目录。公共演示不能替代冷启动GPU复现。训练协议与评测协议的演变仍在历史报告中，不把后来的资源修订冒充原协议成功。

本轮在独立发布分支形成快照。main 和其他实验、界面开发分支不被自动合并。新实验应有单独假设、预算、验证集合与停止条件，不修改本标签追求更高分数。
