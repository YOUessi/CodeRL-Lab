# 评测设计

## 1. 为什么先做评测再训练

CodeRL-Lab 的第一原则是：如果评测不可信，后续监督微调和强化学习得到的“提升”没有意义。

EXP-001 在任何训练之前固定任务格式、执行环境、奖励计算和 Pass@k 口径。

## 2. 公共测试与隐藏测试

每个任务至少包含两组测试：

- **公共测试**：训练阶段可以使用，可形成可验证训练奖励。
- **隐藏测试**：只用于最终评测，不允许进入训练奖励、采样筛选或训练时模型提示。

代码层面，训练奖励函数只接受 `syntax_ok` 与 `public_pass_rate`，没有隐藏测试参数。

## 3. 当前训练奖励

第一版：

```text
总奖励
= 0.10 × 语法正确
+ 0.80 × 公共测试通过率
+ 0.10 × 公共测试全部通过奖励
```

该设计只是 EXP-003 的初始基线，不代表最终研究结论。

## 4. Pass@k

对一个任务采样 n 个候选，其中 c 个通过全部隐藏测试。采用代码生成基准常用的无偏估计：

```text
Pass@k = 1 - C(n-c, k) / C(n, k)
```

项目不会只报告 Pass@1。能力边界实验必须同时观察更大的 k。

## 5. 代码执行安全

模型生成代码默认通过 Docker 执行：

- 禁用网络；
- 只读文件系统；
- 限制内存；
- 限制 CPU；
- 限制进程数；
- 丢弃 Linux capabilities；
- 设置 no-new-privileges；
- 单测试超时。

`local` 执行模式只用于仓库内可信测试夹具，必须显式传入 `--allow-unsafe-local`。

## 6. 当前威胁模型的限制

第一版执行器解决的是“避免普通模型生成代码直接污染宿主机”，还不是经过安全审计的恶意代码沙箱。

尤其需要后续专门研究：

- 运行时测试信息窥探；
- 测试框架劫持；
- 资源耗尽；
- 文件系统侧信道；
- 奖励投机。

这些问题将进入 EXP-007，而不是在 EXP-001 中假装已经完全解决。

## 7. 模型输出归一化

基础模型可能输出解释或 Markdown 代码块。评测前使用固定、公开、确定性的归一化规则：

1. 优先提取第一个代码块；
2. 否则从目标函数定义开始；
3. 若仅尾部自然语言导致语法错误，则逐行删除尾部，直到代码可解析且仍包含目标函数。

所有模型使用相同规则。
