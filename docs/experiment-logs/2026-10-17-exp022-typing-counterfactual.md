# 2026-10-17｜EXP-022 缺失类型导入的 Docker 反事实实验

这是机制审计，**不修改** EXP-021 的原始分数、生成答案或训练模型；全部实验仅在 Tang 上执行。

## 实验复现

- 三种子原始完整96题评测：每个训练seed 384组SFT/GRPO配对，合计1152组。
- 原始配对发生文本变化：42/43/44分别60/56/80，共196组。
- 其中正确性翻转43组：27个错误→正确，16个正确→错误；涉及21个唯一任务。
- 16次回退中10次目标错误为`NameError`，并在GRPO输出中检测到 `List[...]` 注解没有显式 `from typing import List`。
- 对这10个固定回退样本只做一个干预：在由原有评分器提取的代码前插入 `from typing import List\n`，其余算法主体不变，保持相同隐藏测试和Docker镜像。
- 结果：**8/10 补充导入后通过原测试**；另外2/10从`NameError`变成`AssertionError`，依然失败。
- 再次使用独立提交的`src/coderl_lab/analysis/exp022_typing_control.py`复现，输出 `count=10, recovered=8`；测试过程没有在 Tang 宿主机上执行生成程序。
- Tang 本地不可公开的审计产物：`artifacts/exp022/paired_flip_audit.json`、`artifacts/exp022/typing_List_control_reproduction.json`。GitHub仅保存代码、摘要及审核说明。

## 解释

类型注解的无导入符号是部分GRPO回退的**具体直接触发因素**，可通过代码级受控修正得到强证据。它不等于强化学习奖励造成了错误；也不证明GRPO整体算法性能已提升。

必须区分：(a)代码/依赖可执行性、(b)算法逻辑与边界条件、(c)生成采样多样性、(d)外部奖励任务不匹配。当前16次回退中8次由这一行导入直接修复，剩余8次包含2次补导入后依然算法错误，不得据此调整正式模型正确率。
