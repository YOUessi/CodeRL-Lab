# 研究日志

本文件记录项目级关键决策。单次实验的参数和结果写入 `experiments/`。

## 2026-10-06：项目启动

### 决策 1：GitHub 是唯一事实源

代码、配置、实验计划、结果摘要和失败记录全部进入 GitHub。Tang RTX 4090 只作为 GPU 执行节点。

### 决策 2：先评测，后训练

第一阶段不直接跑监督微调或 GRPO。先完成 EXP-001，确保执行、奖励和 Pass@k 可信。

### 决策 3：代码任务只是实验载体

项目研究对象不是“做一个代码修复器”，而是利用代码的可执行性研究大语言模型后训练：

- 监督微调与强化学习差异；
- 结果奖励与过程奖励；
- 动态采样；
- 探索；
- 能力边界；
- 奖励投机。

### 决策 4：隐藏测试禁止进入训练奖励

隐藏测试只用于最终评测。这一约束同时写入文档与奖励函数接口。

### 决策 5：0.6B 只做冒烟

Qwen3-0.6B-Base 用于验证全流程。主实验模型后续升级到约 1.7B 量级，0.6B 结果不承担主要科研结论。

### 决策 6：模型生成代码默认容器执行

本地执行只用于仓库自带的可信测试夹具。实际模型输出默认 Docker、无网络、资源受限执行。

## 待验证问题

- Tang 当前 Python / CUDA / PyTorch / Docker 环境是否满足实验要求；
- Qwen3-0.6B-Base 在 4090 上的实际生成显存和吞吐；
- 正式训练/评测代码数据集的选择；
- 过程级奖励采用何种可验证状态；
- 动态采样的难度区间是否采用固定阈值或在线自适应。


## 2026-10-07：固定按日期研发记录制度

从 2026-10-07 起，除实验纵向记录外，新增每日研发流水：

- 路径：`docs/daily/YYYY-MM-DD.md`；
- 必须记录当日目标、实际操作、失败、问题定位、修复、结果、Commit/分支和下一步；
- `experiments/` 保存按实验编号组织的完整纵向记录；
- `results/` 保存机器可读正式结果；
- 每日研发日志不得只记录成功结果，失败和返工同样保留。
