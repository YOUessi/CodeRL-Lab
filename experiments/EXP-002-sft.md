## 研究目的

建立与基础模型完全可比的监督微调基线，为后续组相对策略优化（GRPO）对照提供参照。

核心问题不是“训练损失能不能下降”，而是：

1. SFT 对 MBPP validation 的 Pass@1 / Pass@4 提升多少？
2. SFT 是否只是提高 Pass@1，而更大的 Pass@k 变化较小甚至下降？
3. 公共测试和隐藏测试之间的差距如何变化？
4. SFT 是否增加格式正确率 / 降低语法失败？
5. 后续在相同数据与评测条件下，GRPO 相比 SFT 多带来什么？

## TRL 1.14.1 接口修复

首次 32 样本冒烟在构造训练配置时失败：

```text
TypeError: SFTConfig.__init__() got an unexpected keyword argument 'warmup_ratio'
```

检查 Tang 上固定版本的实际接口后确认：

- `SFTConfig` 提供 `warmup_steps`；
- 不提供 `warmup_ratio`。

因此项目仍然在 YAML 中保留“预热比例 5%”这一实验语义，但根据：

- 样本数；
- epoch；
- 单卡 batch size；
- 梯度累积；

确定性换算为优化器更新步数。

32 样本 / 1 epoch 冒烟：1 个预热步。  
374 样本 / 3 epoch 正式配置：4 个预热步。

## 冒烟观察

这只是很小的训练和验证子集，**不能当成正式结论**。

但它已经验证为什么本项目必须同时报告更大的 Pass@k：

- Pass@1：6.25% → 10.0%；
- Pass@4：25.0% → 20.0%。

也就是说，仅看单次命中率会得到“变好”的判断，但当前小规模训练下覆盖能力并没有同步提高。

另外，语法失败从 45/80 变为 49/80，说明 32 条训练数据不足以支持“监督微调改善代码格式”的结论。

这些现象必须在 374 条完整训练 + 90 题完整验证上重新检验。

## 正式评测

在 MBPP validation 90 题上，基础模型和 SFT 模型必须使用完全相同：

- 生成提示；
- 采样温度；
- top-p；
- 最大输出长度；
- 每题采样数；
- 代码归一化；
- Docker 执行器；
- Pass@k 计算。

第一版每题 4 个候选，报告：

- Pass@1；
- Pass@4；
- 语法失败率；
- 公共测试通过率；
- 隐藏测试通过率。

后续能力边界阶段再扩大 k。
