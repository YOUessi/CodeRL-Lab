# EXP-004O：门控改变了轨迹，为什么几乎没有救活正确程序？

**分析日期：2026-10-09。状态：已完成基于三个冻结队列的纯后验审计，不是新的预注册因果实验。**

## 研究动机与问题

此前 EXP-004K 在 MBPP 500 题上预注册的低 margin 单 Token 干预取得净 +8/500（+1.6pp，配对bootstrap CI[+0.4,+3.0]pp）；同一冻结规则迁移至 LiveCodeBench v6 的 EXP-004L，只救活1/175且主CI含0；全新独立 v5 题集 EXP-004N 又得到0/167净增益。

本次明确**不根据两批 LCB private outcome 再调 bias、门槛、window、prompt、模型或生成上限**。将科研矛盾拆成：

- gate是否选择错误输出？
- 低-margin扰动是否真实改变轨迹？
- 轨迹改变之后，模型有没有生成正确替代解的能力？
- 截断、模型能力、分布/执行器差异可以解释多少（此项只能提出竞争假设，不能直接证明因果）？

**不要把K的`changed`擅自补值：**已有聚合 summary未直接记录与L/N同口径的raw trajectory count，因此表中保持缺失。这是可复现性诚实要求。

L中被gate触发的轨迹约80.4%确实改变；N中约82.4%确实改变。它们已改变的输出中，后验真正错误→正确只有1/119（L）和0/117（N）。

L+N合并的**仅描述性比例**为1/236=0.4237%，Wilson 95%区间约[0.0748%,2.3607%]。此区间只刻画计数精度，无法消除两批数据的分布、时间、题型、prompt与评测相关性，也不是预注册组合检验。

## 长度/能力控制：不能归因于一个简单因素

- N的Qwen3-1.7B Base greedy512在167题上通过0题；133题到达512 Token cap，只有44题能成功 AST parse。
- N的SFT greedy512通过4题；延长到1024 Token后仍4题。SFT1024有42题触及1024 cap，137题AST可解析，且其167题的原512前缀都得以保留。
- 因此“只增加完成长度可以恢复本方法成功”不受当前数据支持；但不能凭0对照就把所有问题都判为“模型太小”。SFT与Base也不同于大模型。
- 同样，由于K与L/N题型难度、输入模板和执行器差异显著，**不能将K的高救活率与L/N的低救活率差异直接解释为数学上已证明的任务难度因果效应**。

## 当前科研判断（可证伪但尚未独立验证）

研究方向可进一步表述为：在模型当前策略分布和任务难度下，局部 margin 操作能使输出分叉，却不能保障这些分叉落在可通过验证器的正确程序集合中。

候选的下一阶段假设包括：（1）替代token的局部概率与完整程序正确性低相关；（2）在低能力任务中，上游结构性算法错误早已确定，局部token扰动无法修复；（3）公开测试提供的oracle覆盖面不足以区分能够救活的轨迹。

下一轮必须在**尚未用于方法设计的新题目或新的强模型配置**上单独固定研究问题、控制组、数据来源和成功判据。不可用这些已经观察的LCB v5/v6 private outcomes进行有利调参，并冒充独立复现。
