# EXP-7D：7B SFT 后代码正确率、采样覆盖与程序结构多样性的差异审计

## 2026-10-14 研究问题与状态

**性质：正式完成的事后只读分析（Retrospective audit），不是新模型训练，不是额外独立测试集，也不是因果中介检验。**

在同一 Qwen2.5-7B-Instruct 基础模型、固定 HumanEval+ 164 题与每题4次采样条件下，EXP-7C 已经证明：原始模型 488/656候选正确、142/164题 solved@4；UltraChat TRAIN-011 SFT 后 454/656候选正确、139/164题 solved@4。训练后的回答语言建模 NLL 在独立 UltraChat 留出集降低，但 Python 编程测试发生不同程度的退步。需要回答：

1. SFT 改变了单次生成的正确率还是四次采样的覆盖？
2. SFT 会不会提高输出多样性，却降低正确代码出现的概率？
3. 输出长度、语法错误、超长截断是否能够解释观察到的部分退步？

- 没有重新采样、没有重新判分、没有读取新测试数据，也没有任何模型参数改变。
- 每题4条样本，样本级使用相同 sample index 配对；四次 solved@k 按预先冻结的 sample index 顺序算 k=1,2,3,4。
- 多样性指标：同题4次采样不同的精确代码 SHA 数量，及可以由 Python AST 解析的不同语法树数量。AST 结构差异不等于算法语义差异，因此不能直接称为正确思路多样性。
- 置信区间：**按题聚类配对 Bootstrap**，20,000次、seed42；避免把一题4次采样当4道独立题。
- 正确性完全复用已冻结 HumanEval+ 增广断言输出，不按后验题目答案筛选样本。
