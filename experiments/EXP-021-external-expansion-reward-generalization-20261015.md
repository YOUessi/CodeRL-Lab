# 2026-10-15｜EXP-021 外部分布扩展与奖励泛化机制预注册

基于 EXP-020 三个训练种子 42/43/44 在冻结 MBPP+ 24 题共 288 个配对样本的结果：38 个配对文本改变，但 0 次正确性翻转；每臂每种子正确候选 50/96。

## 研究问题
- H1（分布转移）：训练奖励与外部程序语义正确率间存在脱钩；增加独立任务数后收益仍趋近于零。
- H2（奖励错配）：奖励中部分执行/格式奖励和训练测试实例覆盖不足，允许仅改变程序表面形式而不解决隐藏语义错误。
- H3（探索不足）：固定32步、4代每组与低LoRA更新幅度可能只移动采样输出附近局部概率，不能稳定跨越新题错误边界。以上是待检验假设，不是当前已证因果结论。

## 预注册设计
- 外部 MBPP+：沿用同一数据源 SHA `dc20030b3788fccf617444edcb34138ef13d7e4fafd17bfcb8c1279dbb12399b`，369 个原始结构合格样本，剔除先前24题；固定哈希排序取下一个至少96题。严禁看生成或判题结果后挑题。
- 若源文件不可用，先恢复和校验完全一致的数据源；不得凭空重建替代样本或宣称开始了扩展测试。
- SFT 与 GRPO42/43/44 使用完全相同的公开题目和采样 seed，每题4次生成，生成冻结前模型进程不可读隐藏测试。
- 独立保存 public-only、private-only、manifest 三种产物，SHA 全链路、匿名逐题 verdict、参考答案一致性；候选程序只能在 pinned Docker 内运行。
- 新增 HumanEval+ 或严格按日期截取的 LiveCodeBench 是第二个数据域，不与 MBPP+ 合并为单一总分。优先保存每题指标，按题目聚类做置信区间；统计模型训练种子只有3个，不应宣称高精度总体效应。
- 奖励泛化机制：把训练奖励分解为代码可提取性、可执行性、样例测试通过、额外隐藏测试通过；对有文本变化但正确率未翻转的代码进行盲审归类（语法/格式、等价改写、边界条件、算法错误、异常/依赖问题）。
- 添加固定 SFT（零GRPO）对照；必要时另训格式奖励控制臂，以验证是否仅学会“测试奖励偏好”。
- 结论门槛：报告 pass@1、正确候选分数、至少一次解决、逐题 SFT↔GRPO 翻转、种子方差、执行失败类别；若配对置信区间跨零则标注未确认收益。所有 reference golden 失败均需保留在分母并单独列出。
